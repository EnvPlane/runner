# Bounded logical MySQL copy

`DomainExecutor.ExecuteDomain(ctx, Plan)` executes a metadata-only, UID-bound
item. Main adapts the shared domain contract and owns lease/permission checks,
SecretMaterialization, template sealing, operation dispatch and publication.
This package never marks an environment Ready, installs RBAC/admission policies,
changes a source workload/Secret/PVC, or reads a source datadir.

## Production construction

```go
driver := mysqlcopy.NewProofDriver(mysqlcopy.DriverConfig{
    Commands: nil, // argv-only kubectl; stderr suppressed except bounded probes
    RunnerImage: trustedRunnerDigest,
    MySQLImage: trustedMySQLPlatformDigest,
    ServiceAccount: "default", // tokenless helpers; existing permission only
    AllowRootInit: trustedRootOptIn,
    SourceAdmissionFences: reviewedFenceReceipts,
    Authorize: authorizeCompiledSourceAndCurrentNamespaceLease,
})
transport := &mysqlcopy.KubeTransport{
    Driver: driver, SourceNamespaces: trustedNamespaces,
    RunnerImage: trustedRunnerDigest, MySQLImage: trustedMySQLPlatformDigest,
}
receipt, err := (mysqlcopy.DomainExecutor{
    Transport: transport, Authority: authorizeCompiledSourceAndCurrentNamespaceLease,
}).ExecuteDomain(ctx, immutableItem)
```

Check `err` before consuming a receipt. Each driver/transport instance executes
one plan; dump and restore preflights are synchronized. Injected command runners
must honor context cancellation and implement `pvccopy.AdmissionFenceProbeRunner`
for admission probes. Custom transports must meet all documented safety promises.

`DriverConfig.SourceAdmissionFences` is a trusted onboarding receipt, not a job
flag: source namespace plus exact policy/binding names, UIDs and SHA256 of their
entire JSON specs (plain hex). The approved policy must constrain every RunnerSA
Pod create in that namespace. Its fixed validation message is
`envplane MySQL copy source fence [sha256:<approved authority digest>]` (combined
filesystem message also accepted). Before creation the driver runs a positive
server dry-run and negative extra Secret/source-PVC mount challenges. Only the
exact policy/binding/digest denial counts; disabled admission, warnings, missing
proof and unrelated RBAC denial refuse. No dry-run schedules or persists a Pod.
Policy identity/spec is re-read throughout execution. An operator must hold it
installed through return; this cannot prevent an administrator disabling admission.
Existing filesystem fences must be changed by their owner to the reviewed
combined protocol: a second SQL policy cannot override an existing denial.

## Helper and target protocol

`SourceClientHelperName(Ref)` is `mysqlcopy-source-` plus the first twelve SHA256
bytes in hex of `namespace/name/UID`. Source exec/delete permissions can use that
exact name. Orphans are never adopted or deleted. `SourceClientHelperSpec` exposes
the complete review shape: pinned images, one sleeping MySQL client container,
no source PVC, no token, UID/GID 999, read-only root filesystem, all caps dropped;
root config init has only CHOWN/FOWNER/DAC_OVERRIDE. Secret projections contain
only the exact approved app, separate backup-admin and CA keys. Config/tmp/run
are bounded memory emptyDirs. Root init requires explicit trusted opt-in;
Restricted PodSecurity generally refuses it. We never weaken namespace policy.

Main dispatches `mysql-client-config` to `HelperCLI(ctx,args)`. The CLI takes one
or two triples: user-or-`@/credentials/projected.user`, projected password path,
`/config/app.cnf` or `/config/admin.cnf`. Credentials are never argv, receipts or
logs. The output files are exclusive 0600, owned by UID 999 in memory. Target
init additionally prefixes `--target-claim=<local plan digest>` and
`--target-uid=<actual PVC UID>`; completed restart uses `--target-resume` instead.
No dump is saved locally: kubectl exec -> io.Pipe -> bounded SQL tracker -> exec.
Source connections require VERIFY_IDENTITY TLS with the approved CA and Service
DNS; self-signed/identity-incompatible legacy servers are unsupported until the
operator provisions TLS separately. No insecure fallback is provided.

Target creates a native, empty Filesystem/ReadWriteOnce PVC without clone/data
source, then the server triggers WFFC binding. Root must be wholly empty; even
unexplained lost+found is refused. Its exclusive fsynced claim records the local
immutable plan digest and actual PVC UID. The datadir is created UID/GID 999,
0700 at **`TargetDataSubPath = "mysql"`**. The parent must seal this exact subPath
into the generated application's `/var/lib/mysql` mount before execution. Mounting
the PVC root after restore is incompatible. The source mount is never changed.
The target reuses the owned independently generated Secret with distinct app and
`MYSQL_ROOT_PASSWORD` key/values. No root/app credential is copied from source,
generated by the MySQL entrypoint, printed to logs, or independently overwritten.

Only this owned temporary target Pod may consume the PVC. Namespace UIDs, helper
UIDs/spec/deadlines, source PVC/workload/Service/Pod identities and Secret UIDs are
re-read. Source running/ready container imageID must equal the reviewed platform
digest, even for a digest-declared workload. A floating tag is accepted only with
that exact running imageID and a stable matching StatefulSet template declaration;
unknown index/platform/config-digest equivalence is never guessed.

## Consistency and verification

Default dump is `--single-transaction --skip-lock-tables` for InnoDB, permitting
concurrent application DML. DDL safety is mandatory: a separately approved
backup-admin Secret maintains `LOCK INSTANCE FOR BACKUP` on one non-reconnecting
connection. On-session challenges bind connection ID and server UUID; lost/replaced
connections refuse. Explicit scoped quiescence is available only via a trusted
held `QuiescenceHold`, never annotation/flag/schema-before-after inference.
[MySQL backup locks](https://dev.mysql.com/doc/refman/8.0/en/lock-instance-for-backup.html)
and [transactional dump restrictions](https://dev.mysql.com/doc/refman/8.0/en/mysqldump.html)
define these semantics.

Catalog absence requires direct grants proving complete visibility: SELECT,
SHOW VIEW, TRIGGER and EVENT on the database, plus global SHOW_ROUTINE (or global
ALL PRIVILEGES) on the reviewed admin principal. The dump principal's table
inventory must equal that catalog inventory. BACKUP_ADMIN alone or a filtered
zero count is not sufficient. Our source SQL uses only reads and the backup lock,
never exercises those catalog privileges for DDL. Operator credentials/grants
must already exist; this code cannot create/grant them.

Initial supported scope: nonempty MySQL 8 databases, ASCII-safe database/table
names, primary keys, ordinary InnoDB base tables, no views/triggers/routines/events
or cross-schema foreign keys. MyISAM/MEMORY require separately held quiescence.
Empty databases and incomplete catalog visibility explicitly refuse before PVC
creation. Partition/versioned executable DDL, custom datadir command/args,
accounts/system schemas and unsupported SQL shapes are refused, not silently
omitted. This is logical schema/row transfer, **not** datadir/full-filesystem,
physical backup, CSI snapshot or account/replication migration support.

Bounds cover timeout, total logical bytes, rows, tables and individual SQL statement
size (max 16MiB). These limits do not predict MySQL storage amplification; requested
PVC capacity is separately bound and database/storage-full failures leave a partial
target for owner recovery. The tracker hashes actual streamed bytes, every CREATE
schema and every ordered one-row INSERT. An independent target re-dump must match
logical schema/row hashes and counts (raw audit may differ). Session-only restore settings preserve zero auto IDs, UTC and
foreign-key loading order; cyclic/cross-schema semantics remain scoped as above.

After verified restore, SIGTERM to PID 1 must yield clean MySQL exit code zero
before the immutable ConfigMap receipt is created. Receipt binds local plan digest
(which includes domain lifecycle/template/Secret-gate digests), source PVC/workload/
server UUID, actual target PVC/Pod/Secret UIDs, dump bytes/hash, per-table schema/
row proofs and verified shutdown. Only the numeric AUTO_INCREMENT table option
outside all quotes/column parentheses is excluded from schema comparison: active
DML may advance it. Column attributes, literals, indexes and constraints remain
verified. Logical equality compares table schemas/ordered row hashes/counts;
raw source bytes/SHA256 remain transfer audit, not target re-dump equality.
Completed retry restarts the same target with
the same Secret, validates its claim and re-dumps/re-verifies, shuts down, then
returns the unchanged receipt. Foreign/missing/malformed/partial receipts/data
refuse; target PVC/data/Secrets/receipt are never deleted or overwritten.
Cleanup deletes only helpers created by this execution, with exact UID
preconditions, and waits for their disappearance. Unknown outcomes remain partial.

## Checks and acceptance boundary

```sh
GOWORK=/private/tmp/envplane-pvc-copy.lsMO9m/go.work GOTOOLCHAIN=go1.26.9 go test -race ./internal/mysqlcopy
ENVPLANE_MYSQLCOPY_DOCKER_TEST=1 GOWORK=/private/tmp/envplane-pvc-copy.lsMO9m/go.work GOTOOLCHAIN=go1.26.9 go test ./internal/mysqlcopy -run TestMySQL8EngineConsistentFixture -v
```

Unit/native-protocol tests exercise actual stream bytes, receipt/restart binding,
failure/cancellation, authority refusal, credential separation, catalog blindness,
UID drift, spec mutation and disabled/unrelated admission denial. The opt-in pinned
Docker fixture creates only disposable networkless MySQL servers with RAM datadirs/
configs; read-only dump principal, separate backup-admin lock and active DML writer
verify real SQL behavior without existing apps. It is **not** live Kubernetes TLS,
admission/RBAC/PodSecurity/storage/publication proof. Main's isolated Kubernetes
acceptance harness must prove those boundaries before publication. Database-aware
volume end-to-end acceptance/ticket closure remains with main.
